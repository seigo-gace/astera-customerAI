# Astera Customer AI Edge API

This Cloudflare Worker exposes the Customer AI API while routing accepted requests to the existing webhook internal API. It does not introduce a new gateway or modify the existing webhook foundation.

## API contract

```text
POST /v1/customer-ai/messages
GET  /v1/customer-ai/jobs/:job_id
```

The private result callback is:

```text
POST /v1/customer-ai/events
```

The Worker route is deliberately limited to:

```text
https://api.asterav8.jp/v1/customer-ai/*
```

Other paths on `api.asterav8.jp` are outside this Worker route.

## Authentication

Website and app requests continue to use Turnstile.

External server-to-server API requests use:

```http
Authorization: Bearer <CUSTOMER_AI_EXTERNAL_API_TOKEN>
```

A valid external API token bypasses Turnstile for that request only. Invalid bearer credentials are rejected before delivery to the existing webhook API.

## External API request

```http
POST https://api.asterav8.jp/v1/customer-ai/messages
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "message": "質問内容",
  "locale": "ja-JP",
  "session_id": "session_optional_identifier",
  "message_id": "message_optional_identifier",
  "job_id": "job_optional_identifier"
}
```

Only `message` is required. Missing identifiers are generated by the Worker.

## Runtime flow

```text
HP / APP or authenticated external API
  -> Cloudflare Customer AI Edge
  -> existing webhook internal API
  -> registered private-runtime destination
  -> Private HF Space /internal/customer-ai/accept
  -> Customer AI processing
  -> existing webhook internal API
  -> registered edge result destination
  -> Cloudflare /v1/customer-ai/events
  -> CUSTOMER_AI_RESULTS KV
  -> job polling
```

## Required bindings

```text
CUSTOMER_AI_RESULTS
CUSTOMER_AI_RATE_LIMITER
```

## Required secrets

```text
WEBHOOK_INTERNAL_API_URL
WEBHOOK_INTERNAL_API_TOKEN
RESULT_WEBHOOK_SECRET
TURNSTILE_SECRET
CUSTOMER_AI_EXTERNAL_API_TOKEN
```

These names are declared in `wrangler.toml`; deployment fails when any required secret is missing.

## Remaining Cloudflare account values

Source code is complete. Production deployment requires only account-specific values that must not be guessed:

1. Replace `replace_with_production_kv_namespace_id` with the existing production KV namespace ID used for `CUSTOMER_AI_RESULTS`.
2. Confirm the five required secrets are registered on the existing `astera-customer-ai-edge` Worker.

The route is already fixed in `wrangler.toml`; do not create a Custom Domain for the whole `api.asterav8.jp` host.

## Deployment

From the repository root:

```bash
npx wrangler deploy --config edge/wrangler.toml
```

Do not add `--env production` unless a complete `[env.production]` configuration is deliberately introduced later.

## Release checks

1. External API request with a valid bearer token returns `202 Accepted`.
2. Invalid bearer token returns `401` before webhook delivery.
3. Website and app requests continue to require valid Turnstile.
4. Existing webhook internal API receives `customer.ai.message.requested`.
5. Signed `/v1/customer-ai/events` callback is accepted.
6. Invalid callback signature is rejected.
7. `GET /v1/customer-ai/jobs/:job_id` returns pending or completed state.
8. The Worker route does not match unrelated paths on `api.asterav8.jp`.
